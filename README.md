# AXON · Web App 原型

面向建筑学专业的 AI 辅助设计工具 —— 前端原型（单页应用）。

## 一键启动

**方式 A（推荐）**：双击 `start-web.bat`
静默在后台起一个零依赖静态服务（`server.mjs`），自动打开浏览器，
**没有黑窗口要保留** —— 关掉命令行、关掉终端都不影响它。

**方式 B（以后永远都在）**：双击一次 `enable-autostart.bat`
在当前用户的 Windows「启动」文件夹里放一个快捷方式 —— 以后每次登录系统，
网站自己就起来了，**不用再点任何东西，也不需要管理员权限**。
想取消就双击 `disable-autostart.bat`。

**方式 C（局域网 / 团队演示）**：双击 `start-lan.bat`（首次会弹 UAC 放行防火墙）。

**方式 D（命令行）**：

```bash
cd axon-web

# 安装依赖（若网络不稳，加国内镜像）
npm install --registry=https://registry.npmmirror.com

# 生产模式启动（推荐）
npm run build
npm run preview -- --port 4173

# 或者开发模式（改代码热更新，但首次加载慢）
npm run dev
```

生产模式访问 http://localhost:4173 · 开发模式访问 http://localhost:5173

> 若 `npm` 不在 PATH 中，用绝对路径：
> `C:\Users\40414\.workbuddy\binaries\node\versions\22.22.2\npm.cmd`

### 为什么「昨天还能开，今天又打不开」

根因只有一个：**服务进程被回收了**。
服务原来是跟着某个终端 / 会话一起起的，那个会话一结束、终端一关，
进程就随之消失 —— 4173 端口上没人监听，浏览器当然是「拒绝访问」。
所以「再起一次」只能管这一次，不是解法；真正的解法是让它**不依赖任何会话**：

| 文件 | 干什么 |
|------|--------|
| `server.mjs` | 零依赖静态服务（只用 Node 内置模块，不加载任何 npm 包）。启动先探测 4173：已经有服务就**静默退出**，所以重复双击不会冲突、也不会把端口漂移到 4174；被别的程序占住时自动顺延，实际端口写进 `server.port` |
| `axon-web.vbs` | 静默启动器，`WindowStyle=0` 完全无窗口，轮询到端口后自动打开浏览器 |
| `start-web.bat` | 日常双击用：没产物就先 `npm run build`，再走 vbs |
| `enable-autostart.bat` | 在 Windows「启动」文件夹放快捷方式 → **登录即自动运行**（用户级，不需要管理员） |
| `disable-autostart.bat` | 取消自启 |
| `stop-web.bat` | 只杀占用 4173 的那一个进程 |
| `start-server.bat` | **演示推荐**：隐藏窗口 + 崩溃守护（`watch-server.bat` 崩溃 5 秒自动拉起），关终端不影响 |
| `open-firewall.bat` | 一键放行 TCP 4173（`netsh advfirewall`，自动弹 UAC 提权） |
| `局域网排障指南.md` | 静态 IP、休眠、AP 隔离等完整排查手册 |
| `start-lan.bat` | 防火墙放行（弹 UAC 提权）+ 起服务，给手机 / 同事访问用 |

> `server.mjs` 同时把启动横幅写进 `server.log`，打不开时先看这个文件：
> 里面没有 `--- start ---` 就说明服务压根没起来。

## 两种打开方式

### A. 单文件版（推荐 · 零依赖）

```bash
npm run single
```

产出 **`dist-standalone/AXON.html`** —— 一个约 425 KB 的 HTML 文件，
JS / CSS 全部内联，**双击就能打开，不需要服务器、不需要联网**。

这也是**发给别人最省事的方式**：一个文件发过去，对方双击即可。

> 技术上绕开了两个坑：ES module 脚本在 `file://` 下会被 CORS 拦截，
> 所以单文件版改用 `format: 'iife'` 构建并去掉 `type="module"`；
> 同时 `inlineDynamicImports: true` 把 `React.lazy` 的图纸 chunk 也合进主包，
> 避免出现第二个需要外部加载的 JS 文件。

### B. 局域网共享（团队演示 / 多人协同）

双击 **`start-lan.bat`**，或命令行：

```bash
npm run lan     # build + 以 0.0.0.0 启动生产服务（4173）
npm run ip      # 打印本机所有可访问的局域网地址
```

`vite.config.js` 里已写死：

```js
server:  { host: '0.0.0.0', port: 5173, allowedHosts: true }
preview: { host: '0.0.0.0', port: 4173, allowedHosts: true }
```

同一 Wi-Fi 下的手机 / 平板 / 同事电脑直接打开 `http://<内网IP>:4173/` 即可。
`allowedHosts: true` 同时放行了任意 Host 头，所以套一层域名反代也不会被 Vite 拦。

### 「拒绝访问」自查清单

浏览器提示 **ERR_CONNECTION_REFUSED / 拒绝了我们的连接请求 / 无法访问此网站**，按下面 1→4 顺序排查：

| # | 症状 | 原因 | 解法 |
|---|------|------|------|
| 1 | 任何地址都打不开 | **服务没在跑**（最常见：上次那个终端/会话结束后进程被一起回收） | 演示用 `start-server.bat`（隐藏窗口 + 崩溃 5 秒自动重启）；平时用 `start-web.bat`；想开机就在就再双击一次 `enable-autostart.bat` |
| 2 | 本机 `localhost:4173` 正常，别人不行 | **Windows 防火墙**在拦入站 TCP 4173；当前网络常是「公用」配置，默认 `BlockInbound` | 双击 `open-firewall.bat`（`netsh advfirewall` 放行 4173，自动弹 UAC）；或看《局域网排障指南.md》 |
| 3 | 同事/手机浏览器打开 `localhost:4173` | 别人机器上的 `localhost` 指的是**他自己**，当然连不上 | 用本机的局域网 IP：`http://192.168.x.x:4173/`（IP 会变，用 `npm run ip` 随时查） |
| 4 | IP 也通但加载不全 | 端口/AP 隔离/代理 | 换端口（`node server.mjs 8080`）、关代理、手机热点重试 |
| 5 | 装了自启但还是没起来 | 登录时 `dist/index.html` 不在，或托管 Node 被挪走 | 看项目目录的 `server.log`，里面会写清到底卡在哪一步 |

```powershell
# 管理员 PowerShell 执行一次（放行 4173 / 5173）
New-NetFirewallRule -DisplayName "AXON-4173" -Direction Inbound -Protocol TCP -LocalPort 4173 -Action Allow
New-NetFirewallRule -DisplayName "AXON-5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow
```

**最省事的兜底**：直接把 `dist-standalone/AXON-Lite.html`（约 **12 KB** 极简单文件）拷给对方 ——
纯原生 HTML/CSS/Canvas，**零库、零 CDN、零图片**，双击必秒开；
内置 `window.onerror` 红字拦截，脚本出错也只显示错误条，**绝不白屏**。
它保留核心交互：上传留档（只读原图、不碰 `getImageData`，`file://` 下也安全）、
平/立/剖三视图 Canvas 示意、层数/开间/层高滑块联动。

`dist-standalone/AXON.html`（约 425 KB 完整版）功能全，但依赖浏览器本地资源较多；
极不稳定的设备或极端断网场合优先发 Lite。完整版也已在打包时注入同样的错误拦截（`scripts/bundle-single.mjs` ④），
出错只会在顶部红条提示，不再整页白屏。

其他排查项：目标设备要与本机在**同一网段**（不少企业 Wi-Fi 开了「AP 隔离」，
设备间互访会被拦，此时改用手机热点或内网穿透）；部分网络会封非常用端口，可换 8080。
更完整的静态 IP / 休眠 / AP 隔离排查见 **《局域网排障指南.md》**。

## 加载性能

生产构建拆成 4 个 JS chunk，首屏只加载必需部分：

| 文件 | 原始 | gzip | 加载时机 |
|------|------|------|----------|
| `react-*.js` | 219 KB | 66 KB | 首屏（`modulepreload`） |
| `index-*.js` | 15 KB | 6 KB | 首屏 |
| `style-*.css` | 20 KB | 5 KB | 首屏（阻塞样式） |
| `ResultPanel-*.js` | 16 KB | 5 KB | **懒加载**，点生成后才拉 |

`index.html` 内联了首屏 loading 占位（纯 CSS，无 JS 依赖），
所以白屏时间 ≈ 0，网络差时也是先看到转圈而不是空白。

## 面向大众：每个专业名词都必须当场能看懂

网站面向普通用户，所以**没有一个专业名词是甩给用户自己查的**。`src/glossary.js`
收录 34 条术语，每条强制三件套，缺一不可（`npm run check` ⑰ 有断言卡质量）：

| 字段 | 作用 | 例如「开间数」 |
|---|---|---|
| `plain` | 一句话大白话 + 生活类比 | 「像一排书柜有几格 —— 每一格就是一个开间」 |
| `pro` | 规范里的准确定义，供专业读者核对 | 「相邻两条柱轴线之间的空间为一个开间」 |
| `see` | 在这套图纸上具体到哪儿看 | 「平面图横向轴号 ① ② ③ 之间每一跨」 |

覆盖面：**尺寸**（面宽 / 开间 / 开间数 / 进深 / 层高 / 净高 / 板厚 / 总高度 / 室内外高差）、
**构件**（女儿墙 / 勒脚 / 檐口 / 柱网 / 悬挑 / 底层架空 / 幕墙 / 分格线 / 横向长窗 / 窗墙比）、
**制图**（平立剖 + 等轴测 / 剖切符号 / 轴线轴号 / 标高 / 比例尺 / 线宽分级）、
**方法**（约束优先级 / 一致度 / 交叉校验 / 未建模 / 建筑类型）。

三处触达：

1. **就地悬浮** —— 界面上凡是带虚线下划线的名词，鼠标悬停或键盘聚焦即展开卡片
   （`<Term id>`，纯 CSS `group-hover` / `group-focus-within`，SSR 安全）
2. **名词速查面板** —— 左栏底部「名词速查 · GLOSSARY」，按尺寸/构件/制图/方法分组，可搜索
3. **结果区一句话总览** —— 图纸上方用非专业语言复述这张图在说什么，
   并明确写出「楼梯、隔墙是照片里看不见的，图上刻意留白标注未建模，不是漏画」

控制元件的每个标签（层数 / 层高 / 总高度 / 进深 / 面宽 / 开间数 / 室内外高差）与
求解结果 audit 的每个键名都已挂上解读，`not-italic` 保留原有排版。

## 约束优先级：人工设定绝对大于视觉识别

这是整个工具的底层原则。**一旦用户给出工程参数，算法无条件服从，视觉特征不得覆盖。**

```
user（人工设定） > calib（尺度标定反解） > type（类型常识） > infer（视觉推断）
```

- 每个约束量都是 `{ v, src }`，`src` 记录真正胜出的来源
- `model.audit[]` 输出完整审计链：层数 / 层高 / 开间 / 进深 各由谁决定
- 楼层线由 `±0.000` 起按层高**解析推算**，立面横向线（含幕墙分格）完全不参与判定
- 总高与层数同时给定时自动反算层高；冲突时按来源优先级定夺并记账「已覆盖 / 已忽略」

```bash
node scripts/check-model.mjs   # 47 条断言，验证这套规则真的生效
```

覆盖场景：类型选幕墙塔楼（12–22F 常识）却锁定 1F → 必须只出 1F；
幕墙分格线不得与楼层线产生交集；总高 12m + 3F → 层高反算 3.883；
层高 1.5m → 触发 PHYSICS VIOLATION 并降级；未清洗 → 保守空壳。

### 物理常识硬边界

| 量 | 区间 | 超界后果 |
|---|---|---|
| 层高 | 2.2 – 7.0 m | 告警 + 楼梯排不出合规踢面 |
| 门洞高 | 2.0 – 2.4 m | 夹紧到边界 |
| 窗台高 | 0.4 – 1.2 m | 夹紧到边界 |
| 楼梯踢面 | 0.15 – 0.20 m | 告警 |
| 开间 | 2.4 – 9 m | 告警 |
| 进深 | 3 – 20 m | 夹紧到边界 |

**降级原则：宁可输出缺细节的空壳，绝不输出比例错误的精美假图。**
触发条件为「存在物理违背 / 未完成场景清洗 / 关键尺寸来自纯推断」任一，
此时窗构造层次等展开细部一律省略，只保留结构框架。

> 注意区分两条独立的控制线：
> `detail`（构造细部展开）由置信度自动降级；
> `interior`（楼梯 / 隔墙 / 家具）**永远只认人工声明**，与置信度无关 ——
> 置信度再高也不能让算法自己脑补一个楼梯出来。

## 剖面：照片里没有楼梯，剖面就不许有楼梯

这是本版最重要的一条红线。剖面图允许画两类东西：

1. **剖切面切到的实体**（外墙 / 楼板 / 屋面 / 基础 / 地坪），用 poché 表达；
2. **剖切面以外确实看得见的轮廓**，用 0.25b 细线表达。

而**楼梯、内隔墙、家具在照片上完全不可见** —— 画出来就是纯脑补。
因此 `model.js` 引入「人工声明」机制：

```js
interior: { stair: false, partitions: false, furniture: false }  // 默认全关
```

- 未声明 → `model.stair === null`，剖面**一个踏步都不画**，
  室内空间用橙色细虚线框出并标注「室内无视觉证据 · 构件未建模」；
- 未画的项进 `model.omissions[]`，在**图纸左上角**和结果面板里显式列出，
  让读者知道这是克制而不是遗漏；
- 用户在左侧「内部构件（需人工声明）」勾选后，才按层高排出合规踢面/踏面
  （0.15–0.20 m），并在剖切索引上标注「剖切经过楼梯间（人工声明）」。

> 一句话：**图纸上「没画什么」必须写得和「画了什么」一样清楚。**

## 立面：按 GB/T 50104 / 50001 落地

| 规范项 | 实现 |

## 多视角真实分析：多传一张图，结论就得变

**背景（本轮修掉的最大缺陷）**：之前 `App` 只把「上传张数」和「平均宽高比」喂给生成器，
图片内容一个像素都没读过 —— 传 1 张和传 5 张走的是同一套随机数，出来的图一模一样。

```
上传 N 张图
   ↓ ① src/vision.js  每张图真实解码 → Sobel 边缘 → 行/列投影 → 结构化证据
   ↓ ② src/fuse.js    多视角投票 / 冲突登记 / 与「只传第一张」对照
   ↓ ③ src/model.js   视觉证据以 src:'vision' 进入约束求解（优先级高于类型常识）
   ↓ ④ 图纸 + 审计    每张图贡献了什么，直接写在结果面板上
```

### ① 每张图真的被读出了什么（`src/vision.js`）

| 提取项 | 算法 | 用于 |
|---|---|---|
| 水平结构线 | 灰度 + Sobel → 行投影 → 峰值 + **覆盖率>42%**（排除噪点） | 楼层带数量 → `floors` |
| 竖向结构线 | 列投影峰值 + 覆盖率>45% | 竖向分格 → `bays` |
| 底部暗带 + 柱列振荡 | 底部 34% 亮度 vs 全图均值 + 边缘过零计数 | 底层架空 → `structure: pilotis` |
| 冷色低饱和像素占比 + 网格密度 | `(b−r)>6 且 饱和<0.42` 计数 | `fenestration: curtain / ribbon` |
| 顶部连续「亮且无边缘」带 | 逐行扫描 | 建筑体轮廓顶、女儿墙判定 |
| 中央贯穿竖线 + 左右明度差 >0.045 | 峰值 + 分块均值比较 | **转角 → 一次看到两个立面** |
| 转角左右段宽度比 | 几何比值 | 面宽/进深比 → `depth` |
| 列投影镜像相关 | 自相关 | 立面是否对称 |

`npm run check` 里有 **⑭ 像素级算法回归**：合成一张带 3 条楼板线 + 4 条竖线的图，
断言这些线必须在 ±3 px 误差内被检出 —— 证明它真的在算像素。

### ② 融合规则（`src/fuse.js`）

- **票数门槛**：至少半数可用视角同意，结论才以 `src:'vision'` 写入；票数不足降级为 `infer`
- **冲突登记**：各视角读数不一致时写进 `conflicts[]`，图纸上红字列出
  （例：「楼层带 3/5/4 层，按众数 5 层定性」）
- **观测立面**：每多一个独立机位就多一个可视立面，转角视角一次给两个面。
  平面图上的「观测 / 未观测」标注随之变化 —— 这是多传图最直接的收益
- **单视角对照**：同时算一份「只传第一张」的结果，UI 用删除线列出 delta，
  回答「多传的图到底改变了什么」

### ③ 方案变体：重新生成必须不一样

同一批照片在未被人工作锁定的自由度上本来就存在多个合规解。每次求解抽一个变体，
**且一次生成里的 9 轮采样共用它**，避免被中位数共识磨平：

| 维度 | 取值 | 影响 |
|---|---|---|
| `wwr` | 0.34 / 0.44 / 0.52 / 0.62 | 窗宽 → 窗墙比 |
| `rhythm` | uniform / grouped / accent | 实墙分布、端部通高玻璃 |
| `entry` | center / left / right | 立面与平面上的入口位置 |
| `eaves` | plain / cornice / recessed | 女儿墙 ±0.25 m |
| `grid` | bay / half-bay / double-bay | 结构柱网是否与立面同距 |

变体**永远不会覆盖人工锁定项**（`npm run check` ⑬ 有断言），也**不会制造新的物理违背**。
结果面板会标出本次采用的变体编号（`V-xxx`）。

> ⚠ 单文件版（`AXON.html`）用 `file://` 直接打开时，浏览器会因同源策略禁止读取像素，
> 逐视角分析会显示 SecurityError 提示。要完整体验多视角分析，请用 `start-lan.bat`
> 起本地服务后再访问。

## 准确性优先：慢下来的时间用在哪

生成管线约 24 秒，多出来的时间不是空等 —— 是四次真实计算：

**① 逐视角视觉证据提取**：每张上传图解码 → Sobel → 行列投影 → 结构线 / 架空 / 玻璃 / 转角
详见上面的《多视角真实分析》一节，加上可以看到每张图读出的具体数字。

**② 多视角证据融合**：各视角投票取共识、登记视角之间的冲突、
并额外算一份「只传第一张」的结果用来做 delta 对比。

**③ 多轮采样一致性求解（9 轮）**
同一约束、9 个随机起点各解一次，对 bays / depth / floors / floorHeight / length
取中位数作为共识真值，再选与共识最接近的那一轮作为最终模型
（而不是把各轮结果拼成一个自相矛盾的体）。
各轮分歧越大 → 一致度越低 → 自动降级为保守表达：

```
refine  9 轮 · 一致度 96%
consensus  bays=6 depth=19 floors=1 floorHeight=2.58 length=21.48
```

**④ 平立剖 + 平面交叉校验**
| 校验项 | 不通过时会发生什么 |
|---|---|
| 剖切线距柱心 ≥ 0.4 m | 剖到柱上就看不见室内 → 自动移到柱跨中点 |
| 平面洞口与立面 openings 一一对应 | 计入冲突并降级 |
| 窗顶不得越过上层楼板底 | 窗高被 `净高 − 板厚 − 窗台` 硬上限兜住 |
| 门洞高不得大于层高净空 | 告警 |
| 柱必须落在轮廓内 | 告警 |
| 总高 = 层数 × 层高 ± 0.05 | 告警 |

结果直接显示在图纸图签与结果面板上（`refine` / `cross-check` 两行）。

## 场景清洗：色框是真在算像素（`src/detect.js`）

**上一版这里是假的**：`heuristicCandidates(W, H)` 只看画布宽高，用算术取模随机撒 5 个框
再随机贴一个类别标签 —— 图片一个像素都没读过，所以「把汽车认成树」是必然结果，不是偶发 bug。

现在跑真实管线：

```
画布降采样（max 520px）
  ↓ ① 语义掩膜    肤色（RGB ∧ YCbCr ∧ HSV 三票）/ 绿度超额指数 / 天空
  ↓ ② 稀有色判别  面积判据 + **行簇重复计数** + **二维散布** + 颜色族传播
  ↓ ③ 连通域      8 邻域 BFS，单遍统计包围盒 / 像素构成 / 色差 / 边缘密度
  ↓ ④ 形状打分    竖高比 · 填充率 · 面积占比 · 贴地性 · 颜色方差
  ↓ ⑤ 合并过滤    头与身分离则同类并框；过大者判为建筑本体剔除
  ↓ ⑥ 尺度复核    用人 ≈ 1.7 m 反推 px/m，再回头验算各类的物理尺寸
```

| 判据 | 解决的误判 |
|---|---|
| 肤色要过 **三道**规则（HSV 色相 ≤25°、饱和 0.12–0.50） | 米黄色石材、红砖幕墙不再被当成人 |
| **行簇重复计数 ≥3 段** → 判为立面阵列 | 一排排重复立窗不再被当成 5 辆车 |
| **二维散布**（行 × 列都要摊开才算材质） | 路灯这种「竖着占满很多行、只占极少列」的物体能被揪出来 |
| 颜色族传播（26 邻域） | 带光影渐变的石材不会被整片误报 |
| 人体 1.7 m 反算实尺寸 | 3.7 m 高的巨块当场被踢出「车辆」类并记进纠偏日志 |

`npm run detect` 会**合成一张已知真值的街景**（人 / 红车 / 树 / 灯杆 + 带渐变的重复立面），
断言每个物体的检出框与真值 IoU > 0.4、类别正确、并且错觉性的巨块必须被纠偏。

### 识别错了必须能被纠正

- 每个框带**置信度**；<55% 用虚线框 + 「待确认」，宁可说不确定也不假装认得
- 点左上角**彩色标签**展开：判定理由（如「肤色像素 14% · 竖高比 2.9 · 底部贴地」）、
  实算尺寸，以及**一键改判**为其他类别 / 标记「不是干扰物（保留）」
- 改判记录会显示出来（`人工改判 n`），并由「应用清洗结果」带进下一级管线

> ⚠ 单文件版用 `file://` 直接打开时，浏览器会因同源策略禁止 `getImageData`，
> 面板会提示并退回纯手工笔刷模式。要用真实识别请起本地服务。

## 尺度标定：四类量测

在预览图上点「标定」→ 选量测类型 → 在图上点两点 → 输入真实值：

| 类型 | 用途 | 写入的约束 |
|---|---|---|
| 尺度基准 | 量门洞 / 车位 / 人体等参照物，反解 px/m | `span`（面宽）+ 全局比例尺 |
| 首层标高 | 竖向量首层层高 | `firstFloor` → 层高 |
| 总高度 | 竖向量 ±0.000 到檐口 | `totalH` → 反算层高 |
| 关键进深 | 水平量建筑进深 | `depth` |

标定值以 `calib` 级写入，优先级低于人工设定、高于类型常识。
有标定时尺寸精度 **±2.2%**，否则退化为**类型先验 ±8.5%**。

## 楼层判定 ≠ 开窗行数

原型里刻意把这两件事做成**互不相干的两条数据链**：

- `levels[]` —— 楼板结构标高，来自「楼板边缘聚类」，`evidence.floorFrom` 字段写死
- `openings[]` —— 立面开洞，每个洞有独立的窗台/窗顶标高，且**不跨楼层线**；
  另有约 14% 的「实墙开间」随机出现

图纸上层线型也不同：楼层线是**粗实线 + 标高三角**，门窗是**细线 + 玻璃斜纹**，
两者都配了图例，可分别开关。这是为了避免单视角重建里最常见的误判：
把立面上一排窗错认成分层依据。

## 多轮对话反馈修改（图纸展示区下方）

生成完成后，图纸下方有一个对话区：输入「把窗户改大一点」「改成 5 层」「加个阳台」，
引擎会**真的改图**并告诉你改了什么。它强制执行四条铁律（`src/feedback.js`，99→121 条校验中的第 ⑱ 组专门盯它们）：

| 铁律 | 落地方式 |
|------|----------|
| ① 必须解析意图、真改 | 每条意见映射为参数覆盖（层数/层高/开间/面宽/进深/总高）或构件意图（窗缩放 / 加门 / 门加宽 / 阳台）；构件意图经 `applyOpsToOpenings` 真正改写 openings 数据 —— 立面/剖面/平面共用同一份数据，自动三视图一致；阳台由立面绘制层真实渲染（挑板双线 + 栏杆竖条 + 编号 Bn）。没有任何规则命中 = 拒绝执行 |
| ② 最新意见优先 | patch 一律打 `src:'user'`，约束优先级 user > calib > vision > type；右侧参数面板同步显示新值 |
| ③ 给出修改说明 | 每次应用生成 changes[]，对话气泡显示「收到，已将…；正在重新生成…」，含与上一版的差异（如「层数由 5 层改为 3 层」） |
| ④ 容错拒绝 | 「好看点」「优化一下」等模糊意见、坡屋顶等暂不支持的能力，明确回复「抱歉，请给出更具体的修改指令」+ 示例，绝不假装修改 |

**currentState 结构**（App.jsx）：`{ c: 最新约束, ops: 累积构件意图, lastModel: 上一版模型, lastSvg: 上一版立面 SVG }`。
换一批照片即清零；「发送 / 重新生成」后走完整 22 秒管线（准确性优先）。

**接真实 AI 后端**：`buildPrompt(currentState, text)` 已备好完整 Prompt 模板
（四条铁律写死在指令里 + 基础参数 + 累积意图 + 上一版参数与 SVG），
把本地解析器替换为模型返回的 JSON patch 即可，其余管线零改动。
